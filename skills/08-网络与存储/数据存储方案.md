# 数据存储方案

## 概述
Android 端「存数据」没有银弹,选型由**数据形态**(配置 KV / 关系结构 / 大文件二进制 / 敏感凭据)和**访问模式**(高频小读写 / 批量查询 / 流式)共同决定。配置类轻量 KV 历史上由 **`SharedPreferences`(SP)** 承担,但它在**主线程同步加载、`apply` 异步落盘可能丢数据、`MODE_MULTI_PROCESS` 多进程失效**等坑上积重难返,官方已明示用 **Jetpack DataStore** 替代;对极致性能场景,**微信开源的 MMKV**(mmap)提供更快、真正多进程安全的 KV;结构化关系数据走 **Room**(SQLite 封装),大文件走文件系统(**分区存储 Scoped Storage**),敏感凭据进 **Android Keystore** + **EncryptedSharedPreferences**。它们彼此**互补而非互斥**:同一 App 里「配置用 DataStore/MMKV、列表用 Room、token 用 Keystore」是常态。

## 核心原理 / 关键点

### 1. 存储选型矩阵(KV vs DB vs 文件、同步异步、场景)
- 按**数据形态**+**访问模式**+**一致性**+**同步异步**四维选:
  - 简单配置 KV(用户偏好/开关/单值)→ **DataStore / MMKV**。
  - 结构化关系数据(列表/外键/复杂查询)→ **Room**。
  - 大文件/二进制(图片/音视频/下载)→ **文件系统 + MediaStore**。
  - 敏感凭据(token/密钥/密码)→ **Keystore + EncryptedSharedPreferences**,绝不裸存。
- 决策树:轻量 KV → DataStore(官方/异步)或 MMKV(极致性能/多进程);关系数据 → Room;大文件 → 文件系统;敏感 → 加密存储。Room 与 KV **互补**(列表用 Room、配置用 KV),别用 Room 存单值配置(杀鸡用牛刀)。

| 形态 | 首选 | 一致性 | API |
|---|---|---|---|
| 配置 KV | DataStore / MMKV | 最终 / 强(SP 弱) | suspend + Flow / 同步 |
| 关系结构 | Room | 事务(ACID) | DAO + SQL |
| 大文件 | 文件系统 | 文件系统 | File / MediaStore |
| 敏感凭据 | Keystore + EncryptedSP | 硬件级 | EncryptedSharedPreferences |

### 2. SharedPreferences(底层 XML、apply vs commit、ANR 与丢数据坑)
- 轻量 KV,底层是 **XML 文件**,位于 `/data/data/<包>/shared_prefs/`。
- `getSharedPreferences(name, mode)` **首次调用时在主线程同步加载整个文件到内存**(Map);文件大 / 慢盘 / 跨进程 → **ANR** 高发点。
- 写入两条路:
  - `apply()`:**先改内存,再异步落盘**(交给 `QueuedWork`),无返回值;**进程被杀 / 崩溃时未落盘的部分会丢**;Android 8.0+ 还要在 `onStop`/`onPause` 等点等待落盘,仍是 ANR 隐患。
  - `commit()`:**同步写盘并返回 `boolean`**,阻塞调用线程,数据立即持久化。
- **类型不安全**:全靠 `getXxx(key, default)` 取,键名拼错编译期发现不了。
- `MODE_MULTI_PROCESS` 多进程已**实质失效不可靠**,多进程并发写会互相覆盖。
- 只能在主线程 `getXxx`(读取走内存缓存),但首次加载本身就是主线程同步阻塞。

### 3. DataStore(Preferences/Proto、协程 Flow 异步、替代 SP、迁移)
- **官方推荐替代 SP**(Jetpack DataStore),两种实现:
  - **Preferences DataStore**:键值 KV,通过 `preferencesDataStore` 委托扩展;键是带类型的 `Preferences.Key`(int/string/bool/long/float/stringSet),无 schema。
  - **Proto DataStore**:类型安全,基于 **protobuf schema**,存强类型对象(需 `.proto` 定义 + Serializer)。
- **基于协程 Flow 异步、非阻塞**:读 `val flow: Flow<T> = data.data`,写 `suspend fun` `data.edit { it[key] = value }`;天然支持响应式,**绝不在主线程同步 IO**。
- **单写者事务一致性**:写操作串行化,避免并发覆盖;读通过 Flow 自动收到最新值。
- 迁移:`SharedPreferencesMigration` 一行声明即可把旧 SP 数据无缝搬过来,旧 key 一一映射后 SP 文件可弃用。
- 无 ANR、线程安全;**代价是 API 全 suspend/Flow,同步业务要适配协程**。

### 4. MMKV(mmap 高性能、微信、全进程安全、对比 DataStore)
- **微信开源**高性能 KV 库,基于 **`mmap`(内存映射文件)**:写内存即等价于写文件,无 `write`/`read` 系统调用开销,落盘近乎瞬时且**进程崩溃也不丢**(内核负责刷盘),值用 **protobuf 序列化**。
- **真正的全进程并发安全**(`MULTI_PROCESS_MODE`):内部用文件锁 + CRC 校验,多进程读写同一实例可靠——这是它相对 SP / DataStore 的硬优势。
- 极致性能(高频小读写场景):状态标记 / 计数 / 缓存等每秒千百次的写入用 MMKV 远胜 DataStore。
- **同步 API**: `mmkv.encode(key, value)` / `mmkv.decodeXxx(key)`,调用简单;支持加密(`MMKV.initialize(..., cryptKey)`)。
- 对比 DataStore:MMKV 更快、同步 API 简单、多进程强,但**非官方、无编译期类型安全、无 Flow**;DataStore 官方背书、异步协程、类型安全(Proto)但稍慢。

### 5. Room(结构化关系数据、与 KV 互补)
- **SQLite 的 Jetpack 封装**,关系型结构化数据首选;三件套:`@Database`(抽象基类,单例)/ `@Entity`(表)/ `@Dao`(SQL 方法接口)。
- **编译期校验 SQL**(注解处理器 `kapt`/`ksp`),拼错字段 / 表名直接编译失败。
- 支持迁移 `Migration`(版本升级改表结构)、索引、事务(`@Transaction`)、FTS 全文搜索、`@Embedded` 嵌套、`Relation` / `@Transaction` 预加载关联。
- 返回值可挂 `Flow<List<Entity>>`(查询结果变化自动推送),与协程无缝。
- 与 KV **互补**:列表 / 关系 / 复杂条件查询用 Room;单值配置 / 偏好用 DataStore/MMKV。简单 KV 用 Room 是杀鸡用牛刀。

### 6. 文件与媒体(内/外存、分区存储 Scoped Storage、MediaStore)
- **内部存储**:`/data/data/<包>/files`、`cache` 等,**App 私有、卸载清除、无需任何权限**,放敏感私有文件。
- **外部存储**:共享存储;Android 10 引入 **分区存储(Scoped Storage)**、Android 11 **强制**,App 只能访问:
  - 自己的专属目录 `getExternalFilesDir(<type>)` / `getExternalCacheDir()`(免权限、卸载清除)。
  - 通过 **`MediaStore`** 访问共享的**媒体集合**(Images / Video / Audio / Downloads / Files),不能再随意读写公共目录(如 `/sdcard/`)。
- `MediaStore` 提供统一的 `content://` Uri 查询 / 插入接口,写入图片/视频通过 `MediaStore.Images.Media.EXTERNAL_CONTENT_URI` + `resolver.insert`,Android 10+ 读他人媒体需 `READ_MEDIA_*` 细分权限(13+)。
- 权限演进:`READ/WRITE_EXTERNAL_STORAGE` 在高版本**逐步弃用 / 自动降级**,改用**按媒体类型细分**的 `READ_MEDIA_IMAGES`/`READ_MEDIA_VIDEO`/`READ_MEDIA_AUDIO`(Android 13+),访问他人 App 的媒体集合才需申请。

### 7. 敏感数据(Keystore、EncryptedSharedPreferences、不裸存密钥)
- **绝不裸存** token / 密钥 / 密码 / 私钥到 SP / DataStore / 普通文件(可被 root 或备份导出)。
- **Android Keystore**:系统级 / **硬件级密钥库**(TEE / StrongBox),私钥**不出硬件**,签名 / 解密在硬件内完成;用于生成与保存非对称密钥对、设置密钥的「用户认证绑定 / 生物识别绑定 / 过期」属性。
- **EncryptedSharedPreferences** / **EncryptedFile**(Jetpack Security):对 KV / 文件透明加密,密钥本身存 Keystore,API 仍是 SP 风格——但底层已加密落盘;适合加密存配置类敏感数据。
- MMKV / DataStore 也能加传输/落盘加密,但**不替代 Keystore**:真正的高价值私钥(支付 / 签名)必须放 Keystore。
- token 策略:用**短期 access token + 长期 refresh token**,refresh token 可绑定 Keystore + 生物识别;登录态过期走刷新而非持久登入。

## 实践经验 / 踩坑
1. **SP 首次加载卡主线程** —— 大 SP 文件(或 `PreferenceManager.getDefaultSharedPreferences` 在 Application 同步触发)在慢设备上直接 ANR;迁移到 DataStore 后首屏不再阻塞。
2. **`apply()` 丢数据** —— 写完 `apply` 立即崩进程,异步落盘没完成 → 配置丢失;对关键写改 `commit()`(接受阻塞代价)或上 DataStore / MMKV。
3. **多进程用 SP** —— `MODE_MULTI_PROCESS` 不可靠,Widget 进程 / 远程服务进程读到的旧值;换 MMKV 多进程模式或 ContentProvider。
4. **DataStore 主线程读** —— `data.first()` 等 suspend 在主线程调会崩(`IllegalStateException`);必须协程作用域 / `lifecycleScope` 内取。
5. **MMKV 类型错读** —— `decodeInt(key)` 存的是 String 会拿到默认值不报错;约定好 key 的类型或包一层封装。
6. **分区存储踩坑** —— Android 11+ 仍用 `Environment.getExternalStorageDirectory().path` 拼路径写文件 → `FileNotFoundException` / 权限拒绝;改用 `getExternalFilesDir` 或 `MediaStore`。
7. **裸存 token** —— 直接 SP 存 access token 被抓包 / 反编译拿到明文;用 EncryptedSharedPreferences 且 refresh token 绑 Keystore + 生物识别。
8. **Room 主线程查** —— 默认禁止主线程 IO(`allowMainThreadQueries` 是坑);用 `Flow` / suspend / `LiveData` 异步取。
