# 移动端安全

## 概述
移动端安全要点:**传输安全**(HTTPS / TLS、证书锁定 pinning 防中间人)、**存储安全**(敏感数据加密存、Keystore 硬件级密钥、不裸存 token / 密钥)、**代码安全**(R8 / ProGuard 混淆、反调试、加壳、敏感逻辑 native 化)、**签名与完整性**(APK 签名 v1–v3、防重打包)、**数据泄露防护**(日志脱敏、剪贴板、防截屏)。绝对安全不存在,目标是提高逆向与攻击成本,保护核心资产。

## 核心原理 / 关键点

### 1. 安全目标与威胁面
安全三性(CIA):机密性、完整性、可用性。移动端威胁参考 **OWASP Mobile Top 10**:不当存储凭据、不安全通信、逆向 / 篡改、弱加密、组件越权等。绝对安全不存在,目标是**提高攻击成本**。

### 2. 传输安全(HTTPS / TLS + 证书锁定)
全站 HTTPS + TLS 1.2 / 1.3。但 HTTPS 仍可能被中间人(用户装了企业根证书 / 被代理)。**证书锁定(certificate / network pinning)**:只信任特定证书或公钥,用 OkHttp `CertificatePatcher` 或 Network Security Config 实现,防中间人抓包。

### 3. 存储安全(EncryptedSharedPreferences / SQLCipher / Keystore)
- 敏感数据(token / 密钥)不裸存 SharedPreferences / 文件。
- **Jetpack Security**:`EncryptedSharedPreferences`(AES 加密)、`EncryptedFile`。
- 数据库加密:**SQLCipher**(见 [[Room 数据库]])。
- 密钥本身放 **Android Keystore**(硬件级 TEE / StrongBox),密钥不出设备。

### 4. 代码安全(R8 混淆 / 反调试 / native 化 / 加壳)
- **R8 / ProGuard 混淆**:改名 / 优化 / 删除,提升逆向难度(但不防逆向)。
- **关键逻辑 native 化**:放 .so(C / C++),反编译难度大。
- **反调试 / 加壳 / 完整性校验**:检测 Frida / 调试器、APK 完整性,商业加固方案。

### 5. 签名与完整性
APK 签名 v1(JAR)→ v2 / v3(整包,API 24 / 26+)→ v4(增量)。**Play App Signing** 让 Google 托管上传密钥。**防重打包**:运行时校验签名指纹,签名不匹配即拒绝运行。

### 6. 数据泄露防护
- **日志脱敏**:Release 不打印 token / 隐私,用 BuildConfig 开关。
- **防截屏**:`getWindow().setFlags(FLAG_SECURE)`(密码 / 支付页)。
- **剪贴板**:敏感内容别进剪贴板(其他 App 可读;Android 12+ 有弹窗仍有风险)。

### 7. WebView 与组件导出风险
- `addJavascriptInterface` 历史漏洞(Android 4.2 前可反射 RCE);只加载可信内容、限制 JS Bridge 暴露面。
- **exported 组件**(Activity / Service / Receiver / Provider)未保护 → 越权调用 / 拒绝服务。非必要 `exported=false`,必要则加权限校验。

### 8. 安全是成本博弈
提高逆向成本、保护核心资产(密钥、计费、协议、隐私)。把「安全等级」与「资产价值」匹配——过度加固影响体验 / 性能,不足则裸奔。

## 实践经验 / 踩坑

1. **HTTPS 仍可被抓包**:用户 / 企业装根证书即中间人。敏感接口加证书锁定。
2. **裸存 token**:逆向后从文件 / sp 直接拿到;用 Keystore 包裹或 EncryptedSharedPreferences。
3. **混淆不等于加密**:ProGuard 改名后逻辑仍可读;核心算法 native 化更强。
4. **exported 组件未校验**:Intent 可被外部触发,造成越权 / 崩溃;最小化导出 + 权限。
5. **FLAG_SECURE 漏设**:支付 / 密码页不设可被截屏 / 录屏泄露。
