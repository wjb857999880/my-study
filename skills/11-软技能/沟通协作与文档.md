# 沟通协作与文档

## 概述
把复杂技术讲给不同对象(对 PM 讲取舍、对新人讲背景)。善用文档(设计文档 / RFC / 决策记录 ADR)沉淀共识、减少重复沟通。异步沟通讲清上下文,会议有结论与 owner。沟通效率往往决定团队上限。

## 核心方法 / 原则

### 1. 沟通决定团队上限

- 技术强但沟通差的人,影响力和协作半径受限。
- **沟通效率 = 团队效率**:误解、重复沟通、信息黑洞都拖慢团队。
- 高级岗的价值很大程度在于**把复杂讲清楚、推动对齐**。

### 2. 对不同对象讲不同话

- **对 PM / 业务**:讲取舍、讲价值、讲"为什么这么久",少讲技术细节。
- **对新成员**:讲背景、为什么这么做、上下文,帮他快速进入。
- **对同行**:讲设计、权衡、坑。
- 核心:**站在对方角度**组织信息,而不是自顾自讲技术。

### 3. 异步沟通讲清上下文

- 文字 / IM / 邮件要把**上下文讲全**:背景、问题、你的思考、你想要什么(建议?决策?知会?)。
- 避免只有结论没有依据,或只有片段让接收方追问。
- 「**把沟通写完整**」是高级工程师的基本功。

### 4. 文档沉淀共识

- 设计文档 / RFC / ADR 把决策与上下文**落下来**,新人可读、减少重复解释、防遗忘。
- 文档是**异步协作的基石**:不是每次都靠开会。
- 好文档 = 未来自己和他人省时间。

### 5. 会议要有结论

- 开会前:明确**目标**(决策?对齐?头脑风暴?)与**议程**。
- 开会中:聚焦、控时、防止跑题。
- 开会后:**结论 + action item + owner + 截止** 记录同步,否则会白开。

### 6. 倾听与确认

- 沟通不是单方面输出,更要**倾听**:理解对方真正的诉求与约束。
- 重要结论**复述确认**,避免"以为对齐了其实没有"。
- 区分"事实 / 假设 / 观点",减少误解。

### 7. 向上沟通与暴露

- 坏消息(延期 / 风险 / 出事)**早说**,别等盖不住。
- 向上沟通给**选项 + 建议**,而不是只抛问题。
- 信任建立在"持续透明"上,而非"报喜不报忧"。

### 8. 冲突与分歧

- 分歧对事不对人:**基于事实与目标**讨论,而非立场对立。
- 找共同目标,用数据 / 验证(spike)化解主观分歧。
- 实在难决:明确决策人 / 升级机制,别无限拉扯。

## 实践经验 / 常见误区

1. **只顾讲技术** —— 对 PM / 新人讲技术细节,对方听不懂;按对象组织信息。
2. **异步沟通没上下文** —— 只有片段,反复追问;把背景 + 诉求讲全。
3. **会议无结论** —— 开完没 action item;结论 + owner + 截止。
4. **坏消息晚说** —— 盖不住才爆;早暴露、给选项。
5. **不沉淀文档** —— 同样的事反复口头解释;用文档沉淀共识。
6. **只输出不倾听** —— 自顾自讲;理解对方诉求、复述确认。
7. **分歧变对立** —— 对人不对事;基于事实 + 共同目标讨论。
