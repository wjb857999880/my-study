# 面试与项目表达

## 概述
面试是项目经验的「结构化输出」:用 **STAR**(情境-任务-行动-结果)讲清难点与你的具体贡献,用**数据**量化成果,准备好被深挖(为什么这么做、还有别的方案吗、踩了什么坑)。能讲透一个项目,比泛泛而谈十个更打动人。

## 核心方法 / 原则

### 1. 面试的本质:结构化输出

- 面试不是"知道多少"的考试,而是**把你的项目经验 / 能力结构化、可信地讲出来**。
- 面试官想验证:**你真的做过、想清楚了、能讲透、有成长**。
- 结构化表达让面试官容易抓住要点、容易深挖。

### 2. STAR 讲项目

- **S(Situation)情境**:业务 / 技术背景、约束。
- **T(Task)任务**:你要解决的问题、目标。
- **A(Action)行动**:**你**具体做了什么、为什么这么做、权衡。
- **R(Result)结果**:成果(用数据),收获与反思。
- STAR 帮你讲得**有结构、有重点、不流水账**。

### 3. 量化成果

- 用**数据**说话:启动降 30%、Crash 率降到 0.1%、包体积减 20MB、日活提升。
- 没数据时讲**可观察的变化**(上线后某问题消失、效率提升)。
- 量化让贡献可信、有说服力。

### 4. 突出"你的"贡献

- 区分**团队做的** vs **你做的**:面试官问的是你的能力。
- "我们做了 X" → 弱;"我负责 / 主导 X,具体做了 Y" → 强。
- 诚实:没参与的部分别说参与了,会被深挖穿帮。

### 5. 准备被深挖

- 每个技术决策准备好回答:**为什么这么做?还有别的方案吗?为什么不用 X?踩了什么坑?如何验证?**
- 深挖是面试官验证"你是真懂还是背的"的方式。
- 讲得越深,越要能扛住追问。

### 6. 诚实与"不会"

- 不会就说不会,别硬编 —— 面试官一追问就露馅,还扣诚信分。
- "我不熟悉 X,但按我的理解可能是……" > 瞎编。
- 展示**思考过程**比答对每一题更受看重(尤其高级岗)。

### 7. 技术广度 + 一个深度项目

- 简历项目:**一两个讲透**(难点、原理、权衡、坑),比泛泛罗列十个强。
- 面试官会顺着你最熟的项目深挖原理(如你提了启动优化,就问启动流程 / 异步 / 工具)。
- 所以深讲的项目,你要真的吃透。

### 8. 反向提问与沟通感

- 末尾"你有什么问题问我们":问**团队、技术栈、挑战、成长**,展示你的关注点与思考。
- 面试也是双向选择,展示职业思考。
- 沟通中保持**自信但不自负、清晰有条理**。

## 实践经验 / 常见误区

1. **流水账讲项目** —— 没重点没难点;用 STAR + 突出难点。
2. **不量化** —— "优化了启动"无说服力;用数据。
3. **混淆团队 / 个人贡献** —— "我们做了";强调"我具体做了"。
4. **背的经不起深挖** —— 追问就乱;真懂 + 准备好为什么。
5. **不会硬编** —— 穿帮扣分;诚实说不会 + 给思路。
6. **泛泛罗列项目** —— 没一个讲透;深讲 1-2 个。
7. **没准备反向提问** —— 显得无关注;问团队 / 技术 / 成长。
