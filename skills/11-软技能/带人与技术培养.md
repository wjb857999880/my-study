# 带人与技术培养

## 概述
资深 → 专家要能带人:目标对齐、任务分配与成长匹配、在 Review 中教学、给反馈(正向 + 改进)、保护团队专注。**培养他人 = 放大自己的技术影响力**——一个人写代码的天花板,远低于带出一支能打团队的上限。

## 核心方法 / 原则

### 1. 为什么要带人

- 个人产出有上限,**带出一支团队 = 放大自己的影响力**。
- 资深 → 专家 / 技术负责人的核心转变:从"自己全干"到"通过他人完成更大的事"。
- 团队成长 = 你的杠杆;带不出人,自己也走不远。

### 2. 目标对齐

- 让成员**理解为什么做**(背景、价值、目标),而不只是"做什么"。
- 目标清晰可度量,成员有方向感与 ownership。
- 定期对齐,防止方向跑偏。

### 3. 任务分配匹配成长

- 分配任务考虑**成员当前水平 + 成长空间**:太简单没成长,太难会挫败。
- 给**有挑战但够得着**的任务(最近发展区),搭配支持。
- 不是"最能干的人干",而是"让合适的人成长着干"。

### 4. 在 Review / 方案中教学

- CR 不只是改代码,更是**教学时刻**:解释 why、指出更好做法、分享经验。
- 方案评审引导成员自己想清楚,而不是直接给答案。
- 「授人以渔」。

### 5. 反馈:正向 + 改进

- 反馈要**具体、及时、基于事实**:别说"做得不好",说"这个接口 X 场景没覆盖"。
- **正向反馈**同样重要:肯定好的设计 / 进步,强化正向行为。
- 改进反馈**私下、建设性**,保护成员自尊;正向反馈可公开。
- 持续小反馈 > 年度大总结。

### 6. 保护团队专注

- 帮团队**挡掉无关干扰**(无效会议、反复变更、外部打断)。
- 给团队**清晰的优先级与空间**,让人能专注把事做好。
- 承担"挡子弹"的责任,让成员敢做事。

### 7. 心理安全

- 营造**敢说、敢试错、敢暴露问题**的氛围;怕犯错会掩盖问题。
- 出了问题**对事复盘、不甩锅**。
- 心理安全是高绩效团队的基础。

### 8. 以身作则 + 持续学习

- 你做不到的别要求团队;**以身作则**(代码质量、态度、沟通)。
- 自己持续学习,才能持续教。
- 承认自己不知道,示范"如何学习"比装懂更有价值。

## 实践经验 / 常见误区

1. **自己全干不放手** —— 累死自己、团队不成长;分配带成长的任务。
2. **只给任务不给 why** —— 成员没方向感、没 ownership;讲清背景与目标。
3. **CR 只挑错不教学** —— 错过培养机会;解释 why、引导自己想。
4. **反馈模糊 / 不及时** —— "做得不好"无意义;具体、及时、基于事实。
5. **只批评不肯定** —— 打击积极性;正向反馈同样重要。
6. **任务太简单 / 太难** —— 没成长或挫败;匹配最近发展区。
7. **没有心理安全** —— 怕错而掩盖问题;对事复盘不甩锅。
