# 哈希表

## 概述
哈希表用哈希函数把 key 映射到桶,**平均 O(1) 查找 / 插入**,代价是无序与额外空间。冲突处理:拉链法、开放寻址。高频:两数之和、去重、计数、O(1) 判存在。注意最坏 O(n) 与扩容 rehash。

## 核心原理 / 关键点

### 1. 哈希表的本质

- 用**哈希函数** `h(key)` 把 key 映射到桶下标,**平均 O(1)** 查找 / 插入 / 删除。
- 代价:**无序**(不能范围查询)、**额外空间**、最坏 O(n)(全冲突)。
- 适合精确查找、去重、计数、缓存;不适合有序遍历 / 范围查询(用树)。

### 2. 哈希函数

- 要求:分布均匀(减冲突)、计算快、确定性(同 key 同结果)。
- 常见:除留余数法 `key % capacity`(capacity 取质数或 2 的幂)。
- 好哈希函数让元素均匀散布,冲突少。

### 3. 冲突处理:拉链法 vs 开放寻址

- **拉链法**:每个桶挂一个链表 / 红黑树,冲突元素挂同桶。Java HashMap 即此(链表超阈值转红黑树)。
- **开放寻址**:冲突时按规则(线性探测 / 二次探测 / 双重哈希)找下一个空桶。无指针开销、缓存友好,但删除需标记。
- 取舍:拉链实现简单、不怕装满;开放寻址省空间、缓存好但实现复杂。

### 4. 装载因子与扩容 rehash

- **装载因子** = 元素数 / 桶数,衡量拥挤程度;超阈值(如 0.75)触发**扩容**(桶数翻倍)+ **rehash**(所有元素重算位置)。
- 扩容是 O(n) 的,但均摊到每次插入仍是 O(1)。
- 阈值是「时间(冲突少)vs 空间(空闲桶多)」的权衡。

### 5. 平均 O(1) 与最坏 O(n)

- 理想哈希下平均 O(1);**最坏**(冲突严重,如恶意构造 key 都落同桶)退化到 O(n)。
- Java HashMap 链表过长转红黑树,把最坏从 O(n) 拉到 O(logn),防哈希攻击。

### 6. 高频应用

- **两数之和**:存「值 → 下标」,一次遍历 O(n)。
- **去重 / 判存在**:集合 Set。
- **计数**:Map<元素, 次数>。
- **缓存映射**:LRU(哈希 + 双向链表)、LFU。

### 7. 与有序结构的取舍

- 要**有序遍历 / 范围查询 / 第 k 大** → 树(TreeMap 红黑树)/ 堆,而非哈希。
- 只要精确等值查找 → 哈希最快。
- 要保持插入顺序 → LinkedHashMap。

### 8. 工程注意

- **可变对象做 key**:对象放进 map 后修改了影响哈希的字段 → 找不到;key 应不可变。
- **null key / value**:不同实现支持度不同。
- **线程安全**:HashMap 非线程安全,多线程用 ConcurrentHashMap。
- **哈希相等**:重写 `equals` 必须重写 `hashCode`(两 equals 对象必须同 hashCode)。

## 实践经验 / 踩坑

1. **重写 equals 不重写 hashCode** —— 作为 key 找不到;两者必须配套。
2. **可变对象做 key** —— 放进去后改字段,哈希变 → 丢失;用不可变 key。
3. **以为哈希表有序** —— HashMap 无序;要序用 LinkedHashMap / TreeMap。
4. **当范围查询用** —— 哈希不支持范围 / 有序遍历;用树。
5. **忽略扩容 rehash 开销** —— 大量插入时一次性 rehash 有耗时;可预估容量预分配。
6. **多线程用 HashMap** —— 并发扩容可能死循环 / 丢数据;用 ConcurrentHashMap。
7. **依赖 null key/value 行为** —— HashMap 与 HashTable 支持不同,别假设。
