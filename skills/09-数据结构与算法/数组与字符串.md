# 数组与字符串

## 概述
数组是连续存储的线性结构,O(1) 随机访问、O(n) 插删。高频考法:**双指针**(对撞 / 快慢)、**滑动窗口**、前缀和。字符串常结合哈希 / 双指针处理子串、回文、匹配问题。

## 核心原理 / 关键点

### 1. 数组:连续存储的特性

- 内存连续 → **O(1) 随机访问**(下标直接算地址);代价是**插入 / 删除 O(n)**(要搬移元素)。
- 读多写少、需随机访问 → 数组;频繁中间插删 → 链表。
- **缓存局部性**:连续访问(行优先)比跳跃访问(按列)快得多,大矩阵尤其明显。

### 2. 双指针

- **对撞指针**(首尾相向):有序数组两数之和、回文判定、盛水容器。
- **快慢指针**(同向):删重复元素、找中点、判环(链表)。
- 前提常是**有序**或**单链表**;核心是每步移动哪个指针以缩小问题。

### 3. 滑动窗口

- 维护一个满足条件的窗口 `[left, right]`,右端扩张、左端收缩,把嵌套双层循环降到 O(n)。
- 适用:**满足条件的最大 / 最小连续子数组 / 子串**(无重复最长子串、最小覆盖子串)。
- 关键:窗口内状态用什么维护(计数 map / 和 / 单调队列)。

### 4. 前缀和与差分

- **前缀和**:预计算 `prefix[i]`,O(1) 查区间和 `sum[l..r]`;适合多次区间求和。
- **差分**:对区间批量加值 O(1),最后还原;适合多次区间修改。
- 二维前缀和同理(容斥原理)。

### 5. 字符串处理

- 字符串本质是字符数组,可套用双指针 / 滑动窗口 / 哈希。
- 子串问题 → 滑动窗口;回文 → 中心扩展 / Manacher;匹配 → KMP / Rabin-Karp(面试一般朴素 + 讲思路)。
- 编码细节:Unicode / 多字节字符、空串与 null 边界。

### 6. 利用单调性

- 有序 → **二分查找**(见排序与二分查找)O(logn)。
- 有序 + 双指针常能把 O(n²) 降到 O(n)。

### 7. 原地操作与边界

- 要求 O(1) 额外空间时,用**原地**双指针覆写(去重、移动零)。
- 边界:空数组、单元素、越界 —— 是数组题最易错处。

### 8. 复杂度意识与面试套路

- 看到「连续子数组 / 子串 + 最值 / 计数」→ 滑动窗口。
- 看到「有序 + 查找 / 配对」→ 二分 / 双指针。
- 看到「多次区间和」→ 前缀和。
- 先想清楚暴力法,再优化;务必先想清边界。

## 实践经验 / 踩坑

1. **数组越界 / 空数组没判** —— 最常见运行时错;先判 null / 空。
2. **滑动窗口状态没维护好** —— 收缩时忘更新计数,结果错。
3. **双指针方向错** —— 无序数组套对撞指针;前提是先排序或本身有序。
4. **二分边界写错** —— 循环条件 / mid / 更新不自洽(见排序与二分查找)。
5. **前缀和下标偏一** —— `prefix[0]` 取 0 还是 `a[0]` 没统一,区间和算错。
6. **原地操作覆盖未读值** —— 覆写前没保存;按正确方向(常从后往前或双指针)写。
7. **忽视缓存局部性** —— 大矩阵按列跳跃访问慢;尽量行优先连续访问。
