# 包体积优化

## 概述
目标是减小 APK / AAB 体积,直接影响下载转化与留存。手段:**R8 / ProGuard** 代码混淆 + 压缩 + 移除无用代码、资源压缩(`shrinkResources`)、图片优化(WebP / 矢量图 / 采样)、**动态 feature** 按需下发、so 库 `abiFilters`、剔除冗余依赖。用 **APK Analyzer / Bundletool** 拆解构成、定基线、持续监控。

## 核心原理 / 关键点

### 1. 为什么重视包体积

APK / AAB 体积直接影响:① **下载转化率**(越大流失越多,尤其在弱网 / 移动数据);② **留存**(占存储、卸载概率高);③ **推广门槛**(应用商店 / 广告平台常按体积分级);④ 首装时间。体积是「能被装上」的前提指标。

### 2. 体积构成分析

先**拆解体积来源**,别盲优化。用 **APK Analyzer**(或 `bundletool`)看构成:

- **dex**(代码)、**res**(资源)、**assets**、**lib**(so 库)、**META-INF** 等。
- 找出占比最大的项,优先攻。

### 3. 代码层:R8 / ProGuard

- **R8**(取代 ProGuard):**代码混淆**(类 / 方法改名,降体积 + 难逆向)+ **压缩**(tree-shaking 移除无用代码)+ **优化**。
- 开启 `minifyEnabled true` + `shrinkResources true`(release)。
- 注意:反射 / 序列化用的类要 `-keep` 保留,别被误删。

### 4. 资源层

- **shrinkResources**:配合 R8 移除无用资源(注意动态拼接资源名的会被误删,用 `tools:keep` 标记)。
- **图片优化**:WebP / 矢量图(VectorDrawable)替代 PNG、按需采样、压缩工具。
- **资源去重 / 收敛**:`resConfigs` 只保留需要的语言 / 分辨率,去掉冗余同名资源。

### 5. so 库(常是大头)

- `abiFilters`:只打包需要的架构(如 `arm64-v8a`、`armeabi-v7a`),别全带(尤其 x86 模拟器用的)。
- so 去符号(strip)、避免冗余三方 so。
- AAB 按设备架构自动拆分下发。

### 6. 动态化

- **App Bundle(AAB)+ Dynamic Feature**:基础包只含核心功能,大功能 / 资源按需下载。
- **插件化**:非首启必需的功能做成插件,运行时下载。
- 大 asset(视频 / 字体 / 模型)按需下发,不塞进包。

### 7. 依赖治理

- 剔除未使用 / 重复依赖(用依赖分析,见 Gradle)。
- 用更轻的库替代重量级依赖(体积 / 方法数)。
- 关注传递依赖带来的隐性体积。

### 8. 持续监控与 CI 卡点

- 定**体积基线**,每次构建记录 APK / AAB 体积,CI 设阈值卡点(超阈值阻断或告警)。
- 体积构成趋势可视化,防悄悄膨胀。
- 关注 download size(AAB 按设备拆分后的实际下载体积)与 install size。

## 实践经验 / 踩坑

1. **没分析就优化** —— 凭感觉压 PNG 却不知大头是 so;先 APK Analyzer 拆构成。
2. **R8 没开 / 混淆配置错** —— release 没开 minify 或反射类没 keep,体积大或运行崩。
3. **so 全架构打包** —— 带 x86 / 多余架构白增体积;abiFilters 按需。
4. **shrinkResources 误删动态资源** —— 资源名拼接的没 keep;用 `tools:keep` 标记。
5. **图片全是 PNG** —— WebP / 矢量更小;按场景替换。
6. **依赖冗余** —— 引了用不上的大库 / 重复功能库;依赖分析剔除。
7. **没体积基线 / 卡点** —— 体积悄悄涨;CI 阈值 + 趋势监控。
