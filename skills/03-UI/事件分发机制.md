# 事件分发机制

## 概述
触摸事件(`MotionEvent`)从 Activity → ViewGroup → View 的分发:`dispatchTouchEvent` → `onInterceptTouchEvent`(ViewGroup) → `onTouchEvent`,构成「分发 - 拦截 - 消费」的 U 型链。关键是理清三个方法与返回值语义。高频应用:**解决滑动冲突**(内外同方向 / 不同方向,靠拦截策略或 `requestDisallowInterceptTouchEvent`)、自定义手势、点击与长按判定。

## 核心原理 / 关键点

### 1. 事件分发解决什么

多个嵌套的 View(如 ScrollView 里套 RecyclerView)同时想响应触摸时,必须有一套规则决定**事件交给谁**。Android 用「事件分发机制」把一个 `MotionEvent` 从外到内传递、再决定由谁消费,避免多个 View 抢事件。

### 2. 三个核心方法

- `dispatchTouchEvent(ev)`:**分发**事件。Activity / ViewGroup / View 都有;ViewGroup 在此决定「自己拦截」还是「下发给子 View」。
- `onInterceptTouchEvent(ev)`:**拦截**判断,**只有 ViewGroup 有**。返回 true 表示父布局要把事件留给自己(不再下发)。
- `onTouchEvent(ev)`:**消费 / 处理**事件。返回 true 表示消费了这个事件。

### 3. U 型传递链与返回值语义

事件从 Activity → ViewGroup → … → View 逐层 `dispatchTouchEvent` 下传;若到最底层没人消费(`onTouchEvent` 都返回 false),则反向逐层上传由父层处理,形成「U 型」。

- `dispatchTouchEvent` 返回值:本层是否消费了事件。
- `onInterceptTouchEvent` 返回 true:事件不再下发、交给自己 `onTouchEvent`。
- `onTouchEvent` 返回 true:消费,后续 MOVE / UP 都发给它;返回 false:不处理,事件回传给父布局。

### 4. DOWN / MOVE / UP 的分发与消费

- 一个触摸序列从 `ACTION_DOWN` 开始,中间若干 `ACTION_MOVE`,以 `ACTION_UP`(或 `ACTION_CANCEL`)结束。
- **DOWN 决定「谁消费这串事件」**:消费了 DOWN 的 View 会收到后续 MOVE / UP。
- 若父布局在 DOWN 之后才想拦截(MOVE 阶段),子 View 会收到 `ACTION_CANCEL`(被迫中断,要清理手势状态)。

### 5. onTouchListener / onTouchEvent / onClick 优先级

View 处理事件的优先级(从高到低):`onTouch(View, MotionEvent)`(TouchListener)→ `onTouchEvent` → `onClick`。

- 设了 `OnTouchListener.onTouch` 且返回 true → 拦截,后续 `onTouchEvent` / `onClick` 都不触发。
- 这解释了「为什么 onTouch 返回 true 就不响应 click」。

### 6. 滑动冲突:同方向 vs 不同方向

- **同方向冲突**:两层都纵向滑动(ScrollView 嵌 ListView),需按「谁该响应」判断(如子列表滑到边界交给外层)。
- **不同方向冲突**:一横一纵(ViewPager 嵌 RecyclerView),按滑动方向的角度 / 距离判定归谁。
- 本质问题:谁拦截、按什么条件拦截。

### 7. 解决滑动冲突:外部拦截法 / 内部拦截法

- **外部拦截法(推荐)**:逻辑在父布局的 `onInterceptTouchEvent` 里,按条件决定是否拦截——清晰可控。
- **内部拦截法**:子 View 不想被父拦截时,调 `parent.requestDisallowInterceptTouchEvent(true)` 禁止父拦截,配合父在 `onInterceptTouchEvent` 对 `ACTION_DOWN` 不拦截。逻辑分散在父子两端、较易出错。
- 经验:优先用外部拦截法。

### 8. 常见场景与现代方案

- ScrollView 嵌 ListView / RecyclerView:列表滑到边界时交给外层滚动。
- ViewPager 嵌 RecyclerView:横向翻页 vs 纵向列表,按方向判定。
- **现代方案**:`NestedScrolling` 机制让子 / 父协作滚动(RecyclerView / CoordinatorLayout 已内置),优先于手写拦截。

## 实践经验 / 踩坑

1. **`onInterceptTouchEvent` 只在 ViewGroup 有** —— 普通 View 没有此方法,直接走 `onTouchEvent`。
2. **DOWN 没消费,后续收不到** —— DOWN 决定整串事件归属;DOWN 返回 false 则 MOVE / UP 不会来。
3. **拦截后子 View 收到 CANCEL** —— 父中途拦截,子收到 `ACTION_CANCEL` 而非 UP,要处理好手势清理。
4. **`requestDisallowInterceptTouchEvent` 时机** —— 必须在父处理 DOWN 之后;且父对 DOWN 不拦截才有效。
5. **滑动冲突方案选错** —— 不分内外拦截法、逻辑乱;优先外部拦截法,集中在父布局。
6. **onTouch 返回 true 吞掉 click** —— 设了 OnTouchListener 且返回 true,onClick 不触发;按需返回。
7. **手写拦截不如 NestedScrolling** —— 新需求优先用内置嵌套滑动机制,少自己造轮子。
