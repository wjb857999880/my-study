# 屏幕适配与多形态设备

## 概述
**屏幕适配**本质是应对 Android 的**碎片化**:屏幕**尺寸**(小到穿戴、大到平板/车机)、**密度**(ldpi~xxxhdpi)、**宽高比**(16:9/18:9/折叠态)、**形态**(直屏/折叠/分屏)千差万别。基础工具是 **dp/sp/dpi** —— 用密度无关单位让同一份 UI 在不同物理屏幕上呈现近似一致的物理大小。2026 年的适配重心已从「多密度切图」转向**响应式 UI**:折叠屏(铰链避让/半折叠态)、大屏(List-Detail 双栏)、多窗口与跨端(手机/平板/穿戴/车机/桌面)形态要求 UI 能随**窗口尺寸实时重排**,而非写死布局。Compose + `WindowSizeClass` + Jetpack WindowManager 是当前主流方案。

## 核心原理 / 关键点

### 1. 适配本质与单位(dp / sp / dpi)

- **dp(dip,密度无关像素)** = px / (dpi / 160);同 dp 在不同密度屏上**物理尺寸近似一致**(系统按 density 缩放)。
- **sp**:字号单位,与 dp 类似但**随用户系统字体设置缩放**,写文字用它、布局用 dp。
- **dpi**:屏幕密度档位 `ldpi(120)/mdpi(160)/hdpi(240)/xhdpi(320)/xxhdpi(480)/xxxhdpi(640)`,mdpi 为基准。
- **逻辑像素(dp)vs 物理像素(px)**:代码写逻辑像素,渲染时系统换算成物理像素。
- 铁律:**布局里绝不写 px**(物理像素随密度变,直接写在不同设备尺寸乱套);切图按密度提供多套(`drawable-xxhdpi` 等)。

### 2. 传统 View 适配

- **ConstraintLayout**:约束布局,**弹性链 / 比例约束 / Guideline**,用扁平结构替代嵌套 `LinearLayout + weight`,是首选根布局;百分比布局(`PercentFrameLayout`)已弃用,改用约束的比例。
- **资源限定符**:
  - `sw<N>dp`(最小宽度,**最常用**):如 `sw600dp` → 平板/大屏,稳定不随旋转变。
  - `w<N>dp` / `h<N>dp`:按当前宽 / 高匹配,随旋转切换。
  - 方向:`land`(横屏)/ `port`(竖屏)。
- `dimens.xml` 多套(`values-sw600dp/dimens.xml`),同一 name 不同数值,布局 `@dimen/xxx` 引用。
- `LinearLayout` 的 `weight` 按比例分配剩余空间(老办法,优先用 ConstraintLayout 链)。
- **今日头条适配方案**:运行时按设计稿宽度**动态修改 `density`**(`displayMetrics.density`),让全 UI 等比缩放;优点一劳永逸、缺点侵入全局 `DisplayMetrics`(影响三方库 / 系统控件),有争议。

### 3. Compose 自适应

- **WindowSizeClass**:按窗口宽度分档(断点 600 / 840dp):
  - **Compact**(<600dp,手机)→ 单栏。
  - **Medium**(600~839dp,小平板/折叠展开)→ 可能双栏。
  - **Expanded**(≥840dp,平板/桌面)→ 双栏。
- **BoxWithConstraints**:运行时拿到 `BoxWithConstraintsScope` 的 `maxWidth` / `Constraints`,按约束动态切布局。
- 自适应写法:`if (widthSizeClass > WindowWidthSizeClass.Medium) TwoPane() else OnePane()`,**用逻辑而非 `sw<N>dp` 限定符**(Compose 不依赖资源限定符)。
- Material3 适配;`Modifier.weight` / `Spacer` 弹性分配;动态字号(`em` 不存在,用 sp + `LineHeightStyle`)。

### 4. 大屏与折叠屏

- **响应式 UI**:窗口尺寸变化(旋转 / 拖拽分屏 / 折叠展开)时**实时重排**,而非重启 Activity。
- **List-Detail 双栏**:大屏并排展示列表 + 详情,小屏单栏导航跳转 —— Jetpack `ListDetailPaneScaffold`(Material3-adaptive)封装。
- **折叠屏**:
  - **铰链避让**:避开 hinge 区域,内容不压在折叠线上。
  - **半折叠态(桌面姿 table-top)**:特定布局(如视频放上半屏、控制放下半屏)。
  - **Jetpack WindowManager**:`WindowInfoTracker` + `FoldingFeature` 感知折叠姿态 / 铰链位置 / 是否半折叠。
- `AndroidManifest` 声明 `android:resizeable="true"`、`screenOrientation` 别锁死;多窗口 / 分屏 / 自由形态(freeform)需支持。

### 5. 国际化与本地化

- **资源限定符**:`values-zh-rCN` / `values-en` / `values-ja`;默认 `values/` 为兜底,匹配失败回退到它。
- 可本地化:字符串(`strings.xml`)、图片、布局、`dimens`。
- **RTL**(阿拉伯 / 希伯来文从右到左):`layoutDirection` 自动镜像;代码用 **`start/end` 替代 `left/right`**;单向图标(如箭头)做镜像版。
- **日期 / 数字 / 货币**:用 `Locale` + `NumberFormat` / `DateFormat` 格式化,别手拼字符串。
- 动态语言切换:`Configuration` 改 `locale` 后 `recreate()`(或 Compose 重组);Android 13+ `Per-App Language Preferences`。

### 6. 暗黑模式与主题

- **Night 限定符**:`values-night` / `drawable-night` 自动按系统暗色切换资源。
- **DayNight 主题**:`Theme.Material3.DayNight`,系统暗色时自动切 night 资源。
- `uiMode` 配置变化(默认 `configChanges` 不处理则重建);切换主题**不重启**用 `AppCompatDelegate.setDefaultNightMode()`。
- **Material You 动态取色**(Android 12+):`DynamicColors.applyToActivityIfAvailable`,从壁纸提取色板(`DynamicColorScheme`)。
- 暗色对比度 / 可访问性(WCAG),文字图标颜色别写死黑。

### 7. 安全区与异形屏

- **WindowInsets**:状态栏 / 导航栏 / IME(键盘)insets;Compose 用 `Modifier.windowInsetsPadding(WindowInsets.statusBars)` 等,View 体系用 `fitsSystemWindows` + `OnApplyWindowInsetsListener`。
- **刘海 / 挖孔**(`displayCutout`):`layoutInDisplayCutoutMode` 设 `shortEdges`(内容延伸到刘海边)或 `never`(避开)。
- 手势导航边缘防误触:留出手势区 insets。
- **沉浸式**:透明状态栏 / 全屏(`WindowCompat.setDecorFitsSystemWindows(false)`),但务必适配 insets,否则内容被状态栏 / 刘海遮挡。

## 实践经验 / 踩坑

1. **布局写死 px / 硬编码尺寸** —— 在不同密度 / 尺寸上错位;改用 dp + 约束比例 / `WindowSizeClass`。
2. **只用 `sw600dp` 不考虑中等宽度** —— 折叠屏展开 600~840dp 段被忽略;用 `WindowSizeClass` 三档逻辑。
3. **List-Detail 在小屏强行双栏** —— 大屏才并排、小屏单栏导航,按宽度类切。
4. **折叠屏没避让铰链** —— 内容压在 hinge / 被折痕切;用 `FoldingFeature` 检测并避让。
5. **暗色模式颜色写死** —— 没有 night 资源 / `DayNight` 主题,切暗色一片黑底白字看不清;用主题属性 `?attr/colorPrimary`。
6. **沉浸式全屏忘适配 insets** —— 标题栏被刘海 / 状态栏盖住;`windowInsetsPadding` 处理。
7. **今日头条方案侵入全局 density** —— 影响三方库 / Webview / 系统弹窗;评估后再用,新项目优先 `WindowSizeClass`。
8. **RTL 漏改 `left/right`** —— 阿拉伯语镜像后布局错位;统一 `start/end` + `paddingStart/End`。
