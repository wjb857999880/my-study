# 多线程与并发

## 概述
协程之外的**传统并发**基础(JVM/Android):**线程与 Runnable**、**线程池**(ThreadPoolExecutor:核心 / 最大线程数、队列、拒绝策略;Executors 几种池及其隐患)、**synchronized 与 ReentrantLock**、**volatile**(可见性、非原子)、**CAS 与 Atomic\***、**wait/notify**、并发集合(ConcurrentHashMap)。Android 主线程模型:UI 只能主线程更新,耗时任务必须异步。这些是理解协程(其调度基于线程池)、Handler、锁优化的前提。

## 核心原理 / 关键点

### 1. 线程基础
`Thread` / `Runnable`:实现 Runnable(无返回值、`run`)或继承 Thread。状态:NEW → RUNNABLE →(BLOCKED / WAITING / TIMED_WAITING)→ TERMINATED。守护线程(`setDaemon(true)`)随主线程退出而终止。`Thread.sleep` 不释放锁、`Object.wait` 释放锁(需在 synchronized 块)。Android 主线程即「UI 线程」,有其专属 Looper。

### 2. ThreadPoolExecutor 七参数与工作流程
构造:`corePoolSize / maximumPoolSize / keepAliveTime / unit / workQueue / threadFactory / handler(拒绝策略)`。
**任务提交流程**(关键考点):提交任务 → ① 线程数 < corePoolSize,新建核心线程执行;② 否则入 workQueue 排队;③ 队列满 → 线程数 < maximumPoolSize,新建非核心线程;④ 仍满 → 触发拒绝策略。
**四种拒绝策略**:Abort(默认,抛异常)、CallerRuns(调用线程自己跑,背压)、Discard(丢弃)、DiscardOldest(丢最老再入队)。
含义:核心线程数 = 平常态并发;队列缓冲;最大线程数 = 峰值扩容上限。

### 3. Executors 四种池及其隐患
- `newFixedThreadPool(n)`:核心 = 最大 = n,**队列是 LinkedBlockingQueue(无界)** → 任务堆积 OOM。
- `newSingleThreadExecutor`:单线程,同样无界队列 → OOM。
- `newCachedThreadPool`:核心 0、最大 Integer.MAX、SynchronousQueue → 瞬时海量线程 OOM。
- `newScheduledThreadPool`:定时 / 周期。
**隐患**:无界队列或无界线程易 OOM,且线程名默认 `pool-N-thread-M` 难定位。生产应**显式 new ThreadPoolExecutor** + 有界队列 + 命名线程工厂 + 明确拒绝策略。

### 4. synchronized 与锁升级
` synchronized` 是 JVM 内建可重入锁,锁对象(实例 / Class)。JDK6+ 引入**锁升级**(无锁 → 偏向 → 轻量 → 重量):
- **偏向锁**:假设单线程,记录线程 ID,无竞争近乎无开销;
- **轻量级锁**:少量竞争,用 CAS + 自旋避免内核态阻塞;
- **重量级锁**:竞争激烈,升级为 monitor(操作系统互斥量),未抢到者阻塞。
升级单向不可降级(JDK15+ 偏向锁逐渐废弃)。特点:JVM 自动加锁释放、不可中断、非公平。

### 5. volatile:可见性、有序性、非原子
- **可见性**:写后立刻刷主存、读强制从主存读(禁止线程缓存旧值)。
- **有序性**:禁止指令重排序(插入内存屏障)。典型用途——双重检查锁单例的 `instance` 加 volatile,防「对象未初始化完被发布」(分配 → 赋值 → 初始化 可能重排)。
- **不保证原子**:`i++` 是读-改-写三步,volatile 下仍非原子,需 `AtomicInteger` 或 synchronized。

### 6. CAS / Atomic / ABA
**CAS(Compare-And-Swap)**:原子地「比较当前值 == 预期则更新」,硬件 CMPXCHG 指令支持,是无锁编程基础;`AtomicInteger.incrementAndGet` 即 CAS 循环。
- **ABA 问题**:值 A→B→A,CAS 认为没变 → 用 `AtomicStampedReference`(版本号)解决。
- **高竞争自旋开销**:CAS 反复失败浪费 CPU → `LongAdder` 分段累加(基值 + Cell[])减少竞争,高并发计数优于 AtomicLong。

### 7. 显式锁 ReentrantLock / ReadWriteLock / Condition
`ReentrantLock`:API 层可重入锁(基于 AQS),比 synchronized 灵活——可公平 / 非公平、可中断(`lockInterruptibly`)、可限时(`tryLock`)、可绑多个 `Condition`(替代 wait/notify)。
`ReentrantReadWriteLock`:读读共享、读写 / 写写互斥,适合读多写少。
`StampedLock`(Java8):乐观读锁,读多写少性能更好,但不可重入、易踩坑。
**AQS(AbstractQueuedSynchronizer)**:ReentrantLock / 信号量 / CountDownLatch 的基石,核心是「state + CLH 等待队列」。

### 8. 并发集合与同步工具
- **ConcurrentHashMap**:并发安全 Map(见 [[Java 核心与 JVM 原理]])。
- **BlockingQueue**:`ArrayBlockingQueue` / `LinkedBlockingQueue` / `SynchronousQueue`,生产者-消费者首选(`put/take` 阻塞)。
- **CountDownLatch**:一次性,等 N 个任务完成(`await/countDown`)。
- **CyclicBarrier**:可复用,N 个线程相互等待到齐再一起走。
- **Semaphore**:许可证,限流并发数。
- **CompletableFuture**(Java8):异步编排、链式组合,声明式并发。

## 实践经验 / 踩坑

1. **Executors 的 OOM**:Fixed / Cached 池因无界队列或无界线程数易 OOM。生产一律显式 `ThreadPoolExecutor` + 有界队列 + 命名 ThreadFactory + 明确拒绝策略。
2. **submit 吞异常**:`execute` 抛出未捕获异常会终止线程并打印;`submit` 把异常封进 Future,`get` 时才抛 ExecutionException——排查易漏。务必设 `Thread.setUncaughtExceptionHandler`。
3. **锁字符串 / Integer 缓存**:`synchronized("abc")` 锁字符串常量(全 JVM 共享)→ 跨类意外互斥;`synchronized(Integer.valueOf(1))` 同理(缓存)。锁应用私有 final 对象。
4. **volatile 不原子**:`volatile int i; i++` 多线程下丢更新,改 `AtomicInteger`。
5. **wait/notify 信号丢失**:`notify` 先于 `wait` 执行则永久等待;用 `Condition`(带版本 / while 循环)或直接用 `BlockingQueue` 避免手写等待。
6. **线程池未关闭**:`shutdown()` 平滑停(跑完队列)、`shutdownNow()` 立即停(中断);忘关可能致 JVM 不退出或线程泄漏。
7. **Android 线程模型**:AsyncTask / HandlerThread 部分已弃用;子线程更新 UI 抛 `CalledFromWrongThreadException`;耗时任务应走协程(见 [[Kotlin 协程]])或线程池 + post 回主线程。
