# 列表与流式架构

## 概述
设计长列表 / 信息流的加载与展示:**分页**(页码 / 游标)、**Paging3**、预加载阈值、占位 / 骨架 / 错误 / 空态、DiffUtil 增量更新、与缓存的联动。难点是「下拉刷新 + 上拉加载」的状态机与各种边界(无更多、失败重试、跳页)。

## 核心原理 / 关键点

### 1. 列表架构的核心问题

长列表要解的几件事:**大数据分批加载**(不全量)、**高效滚动渲染**(复用,见 RecyclerView 四级缓存)、**状态完备**(加载中 / 错误 / 空 / 无更多)、**与数据源 / 缓存联动**。流式信息流还多了瀑布流、无限滚动、动态高度。

### 2. 分页策略:页码 vs 游标

- **页码分页**(offset/limit):简单,但数据变动时易错位、跳页。
- **游标分页**(cursor / nextToken):用上一页末尾标识取下一页,数据增删不乱序、性能稳,**信息流首选**。
- 取舍:稳定有序 / 大数据用游标;简单固定列表用页码。

### 3. Paging3

- Jetpack 分页库:`PagingSource`(数据源,定义如何加载一页)+ `PagingData`(响应式流)+ UI 层(LazyColumn / Adapter)。
- 自动处理:预加载、列表占位、加载状态、错误重试,UI 无需手写滚动监听。
- 适合数据量巨大、需本地 + 远程分页联动的场景。

### 4. 预加载与无限滚动

- **预加载阈值**:用户滚到接近底部时提前加载下一页,避免「滚到底再等」。
- 自己实现:监听滚动,「倒数第 N 项可见」时触发加载。
- Paging3 的 `prefetchDistance` 内置支持。

### 5. 状态完备

列表要显式处理四种状态,缺一不可:

- **加载中**(骨架屏 / 转圈)、**错误**(重试按钮)、**空**(空态插画 + 引导)、**无更多**(底部「没有更多了」)。
- 用枚举状态机管理,避免状态混乱。

### 6. 增量更新:DiffUtil

- 用 `DiffUtil` / `ListAdapter` 计算新旧列表差异,**只更新变化的项**,避免全量 `notifyDataSetChanged`(闪烁、丢动画、性能差)。
- 配合 RecyclerView(四级缓存)做高效 diff 更新。

### 7. 下拉刷新 + 上拉加载状态机

- 下拉刷新:重置到第一页(游标重置 / 页码归 1)。
- 上拉加载:基于当前页继续。
- 边界:加载中不重复触发、失败可重试、已无更多不再请求、刷新与加载并发处理。

### 8. 与缓存联动 + 流式特化

- 本地缓存(Room)+ 远程分页:Paging3 的 `RemoteMediator` 实现「先展示缓存、后台拉远程写回」。
- 瀑布流(StaggeredGrid):动态高度、防跳动。
- 图片占位防错位(见图片加载架构)。

## 实践经验 / 踩坑

1. **页码分页数据错位** —— 列表有增删时 offset 漂移;信息流改用游标。
2. **加载状态不全** —— 缺空态 / 错误 / 重试,用户卡死;四种状态都要有。
3. **全量 notifyDataSetChanged** —— 闪烁、丢动画;用 DiffUtil 精准更新。
4. **预加载阈值不当** —— 太晚用户干等、太早狂请求;按一屏高度调。
5. **刷新与加载并发** —— 同时触发请求竞态;用状态锁。
6. **列表复用错位** —— 异步图片回调时 item 已被复用;按 key 校验。
7. **跳页 / 重复加载** —— 快速滚动触发多次;加载中标志位防重入。
