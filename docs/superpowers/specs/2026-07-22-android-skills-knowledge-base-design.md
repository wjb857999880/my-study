## 1. 背景与目标

本项目不是软件系统，而是一个**基于 Markdown 文档的个人技术知识库 + 熟练度台账**，服务于一名安卓应用开发工程师的长期技术成长。它要解决三件事：

1. **分类管理**岗位相关的专业技能知识点；
2. **考察**每个知识点的熟练度（自评需有依据、可检验）；
3. **规划并长期跟进**学习进度（看得见变化、能持续滚动）。

设计原则：**用文档分类管理，不开发系统**。整套台账必须轻量到能长期维护——个人知识库最常见的死因是模板太重，写两个就放弃。

## 2. 关键决策汇总

| 决策点 | 结论 |
|--------|------|
| 熟练度模型 | 四档中文自评：**了解 / 熟悉 / 掌握 / 精通** |
| 目录组织 | **按 8 大技术领域分类**，每领域一个目录 |
| 长期跟进机制 | **三者组合**：总看板 + 脚本生成 + 阶段目标/里程碑 |
| 台账重量 | **混合**：frontmatter 必填项精简，正文仅「自评依据」必填，其余按需补 |
| 脚本语言 | **Python3 零依赖**（macOS 自带，不污染 Android 项目环境） |

## 3. 目录结构

```
my-study/
├── README.md                  # 项目说明 + 使用方式 + 熟练度标准
├── DASHBOARD.md               # 总看板（脚本自动生成，勿手改）
├── skills/                    # 8 大技术领域
│   ├── 01-语言/               # Java、Kotlin、C/NDK
│   ├── 02-框架与Jetpack/      # Activity、ViewModel、Room、Compose、Navigation…
│   ├── 03-UI/                 # 自定义 View、动画、RecyclerView
│   ├── 04-性能优化/           # 启动、内存、渲染、耗电、包体积
│   ├── 05-架构/               # MVVM/MVI、模块化、组件化、Clean Architecture
│   ├── 06-系统底层/           # Binder、AMS/WMS/PMS、View 绘制原理
│   ├── 07-工程化/             # Gradle、构建变体、CI/CD、热修复、插件化
│   └── 08-网络与存储/         # OkHttp、Retrofit、Room、DataStore、MMKV
├── plans/                     # 阶段目标/里程碑（每季度/周期一个文件）
├── templates/

└── scripts/
    └── build_dashboard.py     # 生成看板（Python3 零依赖）
```

**文件粒度约定**：一个 `.md` 文件 = 一个可独立考察的知识点（如 `Kotlin-协程.md`、`Binder-原理.md`），而非把一整个领域塞进一个文件。命名建议 `主题-子主题.md`，便于排序与检索。

## 4. 知识点文件模板（`templates/skill-template.md`）

每个知识点文件由 **frontmatter** + **正文**组成。

### 4.1 Frontmatter（全部必填，保持精简）

| 字段 | 类型 | 说明 |
|------|------|------|
| `title` | string | 知识点名称，如 `Kotlin 协程` |
| `domain` | string | 所属领域，对应目录名，如 `01-语言` |
| `level` | enum | 现状熟练度：`了解` / `熟悉` / `掌握` / `精通` |
| `target` | enum | 目标级别：`了解` / `熟悉` / `掌握` / `精通` |
| `importance` | enum | 优先级：`高` / `中` / `低` |
| `last_reviewed` | date | 上次自评/复习日期，`YYYY-MM-DD` |
| `next_review` | date | 下次复习日期，`YYYY-MM-DD` |
| `tags` | list[string] | 可选，自由标签 |
| `related` | list[string] | 可选，关联知识点名称 |

> 注：`tags` 与 `related` 为可选；其余字段必填，缺则脚本校验报警。

### 4.2 正文结构（仅「自评依据」必填，其余按需）

```markdown
# <title>

## 概述
一两句话：是什么、解决什么问题。（按需）

## 自评依据  ★必填
为什么给自己评这个 level？举一个做过的项目 / 排查过的问题 / 能讲清的点，
说明它支撑当前 level、又差在哪所以不到更高一档。

## 核心原理 / 关键点
深挖时再补。

## 实践经验 / 踩坑
做过什么、遇到过什么问题。

## 待深入 / 下一步
- [ ] checklist 形式的下一步学习项

## 参考资料
- 链接列表
```

**「自评依据」是落实"考察熟练度"的核心字段**：逼着自己诚实评估，避免随手填个高级别。一个轻量知识点（概述 + 自评依据）和深挖过的重点知识点可以共存。

## 5. 熟练度标准（写入 README，全局统一）

| 档位 | 判定标准 |
|------|---------|
| 了解 | 知道是什么、解决什么问题，但未实操 |
| 熟悉 | 能照着文档/示例独立完成 |
| 掌握 | 能脱离文档独立开发并排查问题 |
| 精通 | 能做架构设计、性能优化、给别人讲明白 |

四档存在严格顺序：了解 < 熟悉 < 掌握 < 精通。脚本内部按数值映射 `了解=1, 熟悉=2, 掌握=3, 精通=4`，据此判断 `level < target`、计算平均熟练度（领域内所有知识点数值的平均，结果四舍五入再映射回档位）、推算复习周期。

## 6. DASHBOARD.md 总看板规格

由脚本生成，**禁止手工编辑**（顶部标注 `<!-- AUTO-GENERATED by scripts/build_dashboard.py -->`）。包含四部分：

1. **熟练度分布** — 了解 / 熟悉 / 掌握 / 精通 各自的知识点数量与占比。
2. **领域分布** — 8 个领域各自的知识点数与平均熟练度。
3. **复习清单** — 按状态分组（三组互斥），逾期组内按 `next_review` 升序排最紧急在前：
   - 🚨 **逾期**：`next_review < 今天`（已过复习日）
   - ⏰ **该复习**：`next_review == 今天`（恰到期）
   - ✅ **正常**：`next_review > 今天`
4. **目标进度** — 列出所有 `level < target` 的知识点（待提升项），及其 `target - level` 的差距。

## 7. 复习周期规则

level 越熟、复习间隔越长。默认建议周期（复习后据此更新 `next_review`）：

| level | 建议下次复习间隔 |
|-------|----------------|
| 了解 | +30 天 |
| 熟悉 | +60 天 |
| 掌握 | +90 天 |
| 精通 | +180 天 |

`next_review` 字段以文件内显式值为准（可手动覆盖建议周期）；脚本只读取与比较，不自动改写文件内容。

## 8. 阶段目标 / 里程碑（`plans/`）

每个季度或学习周期一个文件，命名如 `2026-Q3.md`。格式约定：

```markdown
# 2026 Q3 学习目标

## 目标1：Kotlin 协程 熟悉 → 掌握
- 关联：skills/01-语言/Kotlin-协程.md
- 截止：2026-09-30
- [ ] 读结构化并发原理
- [ ] 做一个 Flow 实战项目
- [ ] 能讲清调度器 / 作用域

## 目标2：……
```

目标完成（checklist 全勾、对应知识点 level 已升）后，在文件内标注完成并归档；新周期新建文件。`plans/` 文件**不**由脚本解析，纯手工维护。

## 9. 脚本规格：`scripts/build_dashboard.py`

- **运行**：`python3 scripts/build_dashboard.py`（从仓库根目录运行）。
- **输入**：扫描 `skills/**/*.md`，解析每个文件的 YAML frontmatter。
- **输出**：覆盖生成 `DASHBOARD.md`（Markdown 表格 + 汇总）。
- **依赖**：**零依赖**。frontmatter 为扁平 `key: value` 与 `list`，用手写简易解析器读取（不引入 PyYAML）。
- **校验**（发现即报警列出，不中断生成）：
  - 缺必填字段（`title`/`domain`/`level`/`target`/`importance`/`last_reviewed`/`next_review`）；
  - `level` / `target` / `importance` 取值不在枚举内；
  - `last_reviewed` / `next_review` 非 `YYYY-MM-DD` 格式；
  - `domain` 与文件实际所在目录不一致。
- **行为约束**：脚本只读 `skills/` 下的知识点文件，只写 `DASHBOARD.md`；不修改任何知识点文件、不读 `plans/`。
- **日期处理**：以脚本运行当天为"今天"，用于逾期/该复习判断。

## 10. 日常工作流（长期跟进闭环）

1. 学完或复习一个知识点 → 更新对应 `.md`：`level`、`last_reviewed`、`next_review`、`自评依据`；
2. 运行 `python3 scripts/build_dashboard.py` → 看板自动刷新；
3. 看 DASHBOARD 的「复习清单」 → 安排本周复习内容；
4. 每季度在 `plans/` 立 → 学完勾选，达成后把对应知识点的 `level` 升上去。
